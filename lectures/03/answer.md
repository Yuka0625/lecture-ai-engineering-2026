# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：同じ「lecNN-start タグとは何か」という質問に対し、エージェントは各回の演習開始時点のコードを示す Git タグだと正しく説明した。素のLLMは教材内の目印・ジャンプ機能だと誤って説明した。エージェントは用語集を参照し、関連する回も示した。
- `--trace` で見えたツール呼び出し（ツール名と引数）：LoRAとQLoRAの質問では `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` が呼ばれた。確認問題の質問では `make_quiz({'lecture': 2})` が呼ばれた。
- 1つの質問での LLM 呼び出し回数（`requests`）：LoRAとQLoRAの質問は 2 回。確認問題も 2 回（ツールを呼ぶ段階と回答を作る段階）。
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)` を追加。指定した回の用語から1つ選び、「この用語の意味は？」という問題と答えを返す。学習内容の理解を確認したいときや、講義の用語で問題を作るよう頼まれたときに使う。

## 宿題

- 取り組んだレベル：基礎・実装
- やったこと：基礎では `app/agent.py` の `INSTRUCTIONS` に「確認問題を出すときは、make_quiz が返した答えも問題と一緒に必ず伝える」と追加し、同じ質問で変更前後を `--trace` で比較した。実装では `save_learning_log(content)` を追加し、Pydantic AI の `requires_approval=True` で登録した。CLI で保存内容を表示して利用者に確認し、承認された場合だけ `learning_log/` に Markdown ファイルを保存するようにした。
- 結果：基礎の比較では、変更前は `make_quiz({'lecture': 2})` の結果から問題だけを提示し、変更後は問題と答えを提示した。ツール名・引数は同じで、どちらも `[usage]` は `requests=2`。実装のテストでは TestModel で承認時に保存されること、拒否時には保存されないことを確認した。
- 気づき・疑問：`INSTRUCTIONS` の指定でツール呼び出しが同じでも最終回答を変えられる。保存のような副作用のあるツールは、利用者の承認が完了するまで実行しない設計が重要。
